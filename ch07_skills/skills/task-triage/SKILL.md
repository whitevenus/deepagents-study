# task-triage

## 用途
把一条开发任务 triage(分诊)成结构化结论,供看板自动归类与排期。

## 步骤
1. **判断类型**:bug / feature / chore / docs
2. **定优先级**:
   - P0:线上崩溃、数据错误、安全问题
   - P1:影响较多用户但有临时绕过方案
   - P2:一般功能/体验问题
   - P3:可延后的优化
3. **预估工时**:S(<0.5天)/ M(0.5-2天)/ L(>2天)
4. **按下面格式输出**

## 输出格式(严格遵守)
```
类型: <bug/feature/chore/docs>
优先级: <P0/P1/P2/P3>
预估: <S/M/L>
理由: <一句话说明定级依据>
```

## 判定示例
- "登录页偶发白屏" → 类型 bug,影响登录核心路径但非全量 → P1,排查偶发 → M
- "把按钮颜色改成品牌色" → chore,P3,S
